## 1. 知识加油站

### 1.1 场景建模 = 变换的批量艺术

美术资产依旧只有三件：立方体、平面、四棱锥（`common/framework/mesh.h`）。
但**一个变换矩阵就是一次"摆放"**：

```
一棵树 = 树干（瘦高的立方体）+ 两层树冠（四棱锥）
一间房 = 房体（立方体）+ 屋顶（四棱锥）+ 门（薄片立方体）
一个镇 = 6 棵树 + 3 间房 + 4 个箱子 + 若干灵感
```

场景里每个道具存成 `Prop { 形状, 模型矩阵, 颜色 }`，渲染时逐个
`setMat4("uModel") → draw()`。**几何体只有一份，实例千姿百态**——这就是实例化思想的雏形。

### 1.2 "贴地"问题：单位几何体的锚点

- 单位**立方体**中心在原点 → 想让高度为 h 的箱子贴地，要 `translate(x, h/2, z) * scale(w, h, d)`
- 单位**四棱锥**底面已在 y=0 → 直接 `translate(x, 起始高度, z) * scale(...)`

想清楚每个几何体的"锚点"在哪，是场景建模 90% 的 bug 来源。

### 1.3 整体旋转：基座矩阵

苏苏要求房子"别排成一排"，所以每间房要转个角度。三个部件（房体/屋顶/门）
必须**作为整体**一起转——第 1 周层级建模的直接复用：

```cpp
mat4 base = translate(x, 0, z) * rotateY(radians(yawDeg)); // 基座
房体 = base * translate(0, 0.9, 0) * scale(2.4, 1.8, 2.0);
屋顶 = base * translate(0, 1.8, 0) * scale(2.9, 1.3, 2.5);
门   = base * translate(0, 0.55, 1.01) * scale(0.55, 1.1, 0.04);
```

### 1.4 光是什么：Phong 反射模型

真实世界的光会弹射无数次（全局光照，电影 CG 那种）。游戏跑 60 帧等不起，
Phong（1975）提出用三个分量**骗过人眼**：

```
最终颜色 = (ambient + diffuse) · 物体色 + specular

① ambient  环境光    = ka · lightColor              看不到光也有保底亮度
② diffuse  漫反射    = kd · max(N·L, 0) · lightColor 表面越正对光越亮
③ specular 镜面高光  = ks · max(V·R, 0)^n · lightColor 反射对准眼睛时的亮斑
```

符号表（全部是**单位向量**，忘记 normalize 是本周第一大坑）：

```
N = 表面法线      L = 指向光源的方向
V = 指向相机的方向 R = reflect(-L, N) 光的反射方向
n = shininess 高光指数：越大亮斑越小越锐（塑料 32，金属 256+）
```

### 1.5 法线的隐秘角落：法线矩阵

法线是"方向"不是"点"，不能直接乘模型矩阵——非均匀缩放会把它掰歪
（想象把球横向拉长，法线要是跟着拉长就不垂直于表面了）。正确姿势：

```glsl
vNormal = transpose(inverse(mat3(uModel))) * aNormal; // 逆转置矩阵
```

顶点着色器里已经写好，本周你只需要知道**为什么**（考点预警）。

### 1.6 纹理映射一分钟入门

地面那张草地格子图不是图片文件——是代码里现生成的 256×256 棋盘格
（`makeCheckerTexture`，美术组不在只能这样）。顶点自带 UV 坐标（0~1），
片段着色器里 `texture(uTex, vUV * 平铺倍数)` 采样即可。GPU 会自动做双线性
过滤和 mipmap。想换成真图片？见"加班挑战"。

### 任务二：工单 SD-202 —— 让世界有光（约 60 分钟）

打开 `starter/src/main.cpp`，片段着色器里有一片巨大的 TODO。
按注释里的公式，把三个分量逐个写出来，**每写一个都跑一遍**：

| 步骤 | 写完后的世界 |
|------|-------------|
| 只有占位的 0.3 | 阴间滤镜，万物灰暗 |
| + ambient | 稍微亮了，但还是"塑料感"平涂 |
| + diffuse | **立体感突然出现**——树冠有了向光面和背光面 |
| + specular | 屋顶和小宇头顶出现太阳的小亮斑，材质感来了 |

写完按 **L** 让太阳转起来：光影随太阳方向流动，阴阳面实时变化——
如果画面纹丝不动，检查你是不是把 `uLightDir` 忘在公式外面了。

> **经典翻车现场**：
> - 整个世界一片漆黑 → `max(dot(N,L), 0.0)` 里的负号方向搞反了（L 应**指向光源**）
> - 高光糊成一大片 → 忘了 `pow(..., 32.0)`
> - 有些面亮得诡异 → 忘了 `normalize(vNormal)`（插值后的法线长度≠1）

## 4. 老周的加班挑战（选做）

- ☆ **昼夜循环**：让 `uLightColor` 随太阳高度从暖黄→橙红→深蓝渐变（日落狙击手）
- ☆☆ **点光源路灯**：Phong 公式里的 L 改成 `normalize(lampPos - vWorldPos)`，加距离衰减 `1/(1+0.1d+0.03d²)`，在镇口立一盏路灯
- ☆☆☆ **真图片纹理**：引入单头文件库 [stb_image.h](https://github.com/nothings/stb)，把草地换成真实草皮照片（顺便理解为什么要 `stbi_set_flip_vertically_on_load`）
- ☆☆☆☆ **Blinn-Phong**：把 `V·R` 换成 `N·H`（半程向量），对比大角度下高光形状差异——这是 90% 现代游戏实际用的版本
